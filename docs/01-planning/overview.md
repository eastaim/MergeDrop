# MergeDrop 기획 개요

## 무엇을 만드는가

같은 과일을 떨어뜨려 합치는 물리 퍼즐 웹 게임. 이른바 "수박게임" 계열이다.

과일을 위에서 떨어뜨리면 상자 안에 쌓이고, 같은 종류 둘이 닿으면 한 단계 큰 과일로 합쳐지면서
점수를 얻는다. 과일이 상자 위쪽 위험선 위에 멈춰 있으면 게임이 끝난다.

```
체리 → 딸기 → 포도 → 한라봉 → 오렌지 → 사과 → 배 → 복숭아 → 파인애플 → 멜론 → 수박
```

플레이어가 떨어뜨릴 수 있는 것은 앞의 5단계(체리~오렌지)뿐이고, 그 위는 합쳐야만 나온다.

## 왜 이 게임인가

첫 웹 게임으로 정한 이유:

- **에셋 없이 성립한다.** 과일이 전부 색깔 있는 원이라 그림 파일 없이 코드로 그려도 게임이 된다.
  아트 리소스를 구하느라 개발이 막히지 않는다.
- **규칙이 순수 함수로 떨어진다.** "같은 티어끼리 합쳐서 다음 티어" 하나가 전부여서 물리 엔진과
  분리해 테스트하기 좋다.
- **점수 기반이라 랭킹과 궁합이 좋다.** 나중에 서버를 붙일 때 자연스럽게 확장된다.
- **한 판이 짧다.** 실패해도 바로 다시 하게 되는 구조다.

## 범위

### 1차 릴리스에 넣는 것

- 조준 → 낙하 → 물리 → 머지 → 점수의 핵심 루프
- 11단계 과일 사다리, 가중치 기반 랜덤 스폰
- 위험선 판정과 게임오버, 재시작
- 최고 점수 기록 (브라우저 로컬)
- 데스크톱 마우스 / 모바일 터치 공통 지원
- GitHub Pages 자동 배포

### 1차에서 뺀 것

| 항목 | 이유 |
| --- | --- |
| 전역 랭킹 | 서버가 필요하다. 대신 `ScoreService` 인터페이스로 확장 지점만 만들어 뒀다 ([ADR-002](../02-architecture/adr-002-점수-저장-추상화.md)) |
| 사운드 | 에셋과 모바일 자동재생 정책 대응이 필요하다. 핵심 루프 검증 후 |
| 실제 과일 아트 | 코드로 그린 원으로 충분히 플레이 가능하다. 텍스처 키만 유지하면 나중에 교체가 싸다 |
| 계정 / 로그인 | 이 게임에 필요한 이유가 아직 없다 |

## 성공 기준

1차 릴리스는 "누군가에게 링크를 보낼 수 있는 상태"를 목표로 한다. 구체적으로:

- 배포된 URL에서 새로고침만으로 즉시 플레이가 시작될 것 (로딩 화면이 필요 없을 것)
- 모바일 브라우저에서 탭만으로 조작이 될 것
- 한 판이 끝나고 다시 시작하는 데 막힘이 없을 것
